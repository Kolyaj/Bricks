# Bricks

npm-пакет `dresscode-bricks` — базовая класс-библиотека методологии DressCodeJS (npm: dresscodejs). `Bricks.inherit`/`create` — фундамент, на котором строятся остальные библиотеки экосистемы (Quantum, Botex, …).

## Знания

- `lib/.dresscode` содержит `.` — библиотека самодостаточна: потребитель объявляет путь `node_modules/dresscode-bricks/lib` в своём `.dresscode`.
- Собственной сборки нет: код собирает потребитель через dresscodejs. Код — ES5 с русскими JSDoc-комментариями.
- Родительский класс в lib не называют по имени: в конструкторах вызовы идут через `MyClass.superclass` (`Bricks.X.superclass.method.apply(this, arguments)`), а не `Parent.prototype.method` — `superclass` указывает на прототип родителя, и при смене цепочки наследования (вставленный промежуточный класс) искать-менять ничего не надо. Важный нюанс: `Bricks.inherit` ставит `superclass` только на **конструктор**; для **инстансов** (синглтоны, напр. `Sound` = `new Bricks.Component({...})`) у него значение `undefined` — там используется `this.constructor.prototype.method.apply(this, arguments)` (тот же динамический принцип со стороны инстанса).
- Сиюминутные комментарии вида «Фикс батч N: …» не живут в коде — обоснование фикса записывается здесь, в строке батча; код читается так, будто писался с таким поведением изначально.
- `Node.compareDocumentPosition(other)` — биты описывают положение other относительно this: 16 (CONTAINED_BY) = other потомок, 8 (CONTAINS) = other предок, 0 = тот же элемент/разъединённые. Отсюда `isAncestor`: `parent.compareDocumentPosition(child) & 16`.
- Legacy-модули `Widget`/`AbstractWidget`/`StringWidget` (UI), `XHR`/`Request` и `Bricks.JSON.parse` помечены `@deprecated` (2026-09): актуальный network-модуль — `Remote`; `lib/lang/` (полифиллы) из пакета удалён.
- Публичные модули не удаляются — строгая обратная совместимость: потребитель, обновивший библиотеку ради нового модуля, не должен ничего потерять. Сборщик DressCode кладёт в бандл только используемый код, поэтому неиспользуемые deprecated-модули бесплатны; `@deprecated` — конечное состояние модуля.
- `DOM.normalizeCSSProperty(name, value, el)` без el имплицитно детектит фичи через `document.documentElement.style` — скрытая browser-зависимость (её же без el вызывает `StringWidget._setStyle`).
- `_createXHRObject` (`window.XMLHttpRequest ? … : ActiveXObject`) продублирован в трёх местах: XHR.js, Request.js, Remote.js.
- Тесты: `npm test` — Node-харнесс `test/node/run.js` (ADR 0003, основной): компилирует `test/tests/*.js` in-process через API dresscodejs (эквивалент `-d`), оборачивает бандл CJS-фабрикой со стандартной инъекцией (`BricksTest`, `window`, `document`, `location`, `ActiveXObject`, `setTimeout`/`clearTimeout` = fake-часы, `describe`, `it`, `assert`); весь сьюит — четыре прохода: `{lang_ru, lang_en} × {sloppy, strict}`; любое падение роняет exit-code — known-red-механизма нет, баги в lib исправляются вместе с созданием тестов (решение 2026-09); конвенция: один тест-файл = один lib-модуль (состав — MANIFEST в run.js, сейчас 19; deprecated-модули не тестируются); fake-часы на `BricksTest.clock`; браузерные профили — plain JS в `test/profile/` (в Node `require`, в браузере один `<script>`), есть `Profiles.el` (батч 1), `style`/`doc`/`event`/`xhr` — батч 2. Браузерная часть — Yaxy (`yaxy --config .yaxy`, тест-файлы компилируются на лету) + `test/index.html` (`mocha`/`assert` из `test/external/`) — остаточный минимум (батч 3): `Cookie` (document.cookie-хранилище), DOM-дерево `Bricks.DOM` (`Bricks.DOM.tree.js`: getEl/getEls/createSelectorFilter/remove/createFragment/setStyle/on/un/unAll/initDrag — реальное дерево, события, innerHTML), `DOM.setStyleProperty` (layout), `Sound._createAudioEl` (`Bricks.Sound.dom.js` — innerHTML); браузерные тест-файлы в MANIFEST не входят.
- Проверка браузерного сьюита без браузера: Yaxy перезаписывает path-формат `req.url` в абсолютный по заголовку Host, и правила `.yaxy` матчатся по полному URL `http://bricks.tests/…` — Host без порта. Значит собранный файл можно достать `curl -H 'Host: bricks.tests' http://127.0.0.1:<port>/tests/X.js` (server: `yaxy --port <port> --config .yaxy`): проверяется только компиляция dresscodejs, сами тесты пользователь гоняет в браузере по `http://bricks.tests/`.
- dresscodejs 2.0.8 не выдаёт `'use strict'` нигде (0 вёрст в lib/); CLI `-d` = `--debug` (не обфусцирует private-имена) — бандлы non-strict по умолчанию. Тело функции, созданной `new Function`, non-strict по спецификации в любом контексте: `arguments.callee` в сгенерированном коде (`Bricks.String.compile`) работает и в strict-бандле (стрик-эксперимент 2026-09); реальный strict-баг — `Bricks.Function.throttle` (callee в обычном IIFE — throw), исправлен в батче 1 (именованный function-экспрессен).
- Тест `Bricks.rand` — единственный недетерминированный в сьюите (глобальный Rnd без seed): порог 400 откалиброван под 10000 выбросов (измеренный максимум разброса 330) — ложных красных нет; не сужать порог без замера распределения (200 даёт флейк ~2.8%). Остальные проверки распределений (Bricks.Rnd, `Array.shuffle`/`pick`) используют фиксированный seed — детерминированы.
- `//#imports` (без аргументов) в тест-файлах разворачивается внутрь IIFE теста → скомпилированный `test/tests/X.js` — самодостаточный скрипт (импорты + тест).
- `EventsController.on` — `fn.call(ctx, evt || window.event)`: событие может прийти через глобал (IE6–8) — ещё одна нормализующая ветка.
- `Number.pluralIndex`: `//#if lang_ru`/`//#if lang_en` — в сборке без `--set lang_*` `index` не присваивается, `plural` вернёт `undefined`; потребитель (и наши тестовые сборки) обязан ставить lang-флаг.
- Батч 1 (2026-09): поведенческие фиксы, найденные тестами — `Date.getDayOfYear` (this→date), `Function.throttle` (strict: `arguments.callee`), `String.endsWith` (равные длины), `QueryString.parse` (`a=b=c`), `Rnd.bool(0)` (всегда false; раньше `|| 50` → монетка), `DOM.toggleClassName` (Boolean по JSDoc; раньше undefined); `Bricks.JSON.parse` — deprecated (тонкая обёртка над JSON.parse, eval-фолбэк исчез, тесты удалены).
- Батч 2 (2026-09): нормализаторы через браузерные профили (`Profiles.style/doc/event/xhr` + conformance-мета-тесты; DOM-листья, Sound, Remote, DragController). Поведенческие фиксы, найденные тестами: `DOM.getViewportSize` (раннее окно без innerWidth → NaN), `DOM.isAncestor` (self: по спецификации compareDocumentPosition(self) = 0, а contains/цепочка дают true — проверяется отдельно), `Sound._initComponent` (базовый вызов отсутствовал — destroy() падал), `Remote` POST/PUT (instance-params из config/setPostParam вообще не участвовали в body; в merge headers теперь выигрывает per-call — симметрия с params). `Sound` — синглтон (`new Bricks.Component`, не конструктор): `new Bricks.Sound` невозможен, экземпляр с другим doc создать нельзя — продуктовое решение open (todo).
- Батч 3 (2026-09): итоговый браузерный минимум в Yaxy — контракт-тесты `Cookie` (очистка хранилища в beforeEach; implicit global `RegExp.$1` → результат `match` — без изменения поведения), DOM-дерево против реального document (`Bricks.DOM.tree.js`, включая touch-ветку initDrag — с guard на `TouchEvent`/`Touch`), `Sound._createAudioEl` (`Bricks.Sound.dom.js`). Дерево/куки/innerHTML — механизмы (решение 2026-09): не mock-уются профилями, проверяются против реального браузера; единственный lib-фикс батча — гигиенический `RegExp.$1` → результат `match` (todo 20260921-6). Первый браузерный прогон поймал баг в самом tree-тесте: тест initDrag объявлял `ctx`, но не передавал его 5-м аргументом — браузерный сьюит гоняется в sloppy (бандлы без `'use strict'`), и `fn.call(undefined)` → `this` = window: обработчик писал в `window.moves`, `checkGlobals` mocha красил тест. Фикс — передавать `ctx`; конвенция: обработчик, использующий `this`, всегда получает явный ctx.
- `docs/adr/` — 0001 «публичные модули не удаляются», 0002 «deprecated не тестируются», 0003 «тесты против браузерных профилей» (полные тексты с trade-off; базис для архитектурных review).
- Релизы — вручную: git-лог показывает коммиты «release 0.x.y»; `package.json` содержит только `dresscodejs` в devDependencies.
