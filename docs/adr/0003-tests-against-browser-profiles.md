# Тесты прогоняются против браузерных профилей, а не в реальном браузере

`dresscode-bricks` на ~80% состоит из браузерных нормализаторов. Решение (2026-09): основная тестовая среда — Node, где хост-объекты заменяются **браузерными профилями** — mock-объектами host-API в интерфейсной форме различных браузеров. Один набор тестов × много профилей: за один проход накрываются различия всех браузеров. Реальный браузер (Yaxy-харнесс) удерживает только то, что нельзя mock-ать.

- **Status**: accepted (2026-09)

## Considered options

- **jsdom / DOM-эмуляция в Node** — **отклонено**: jsdom фальшивит ровно то, что проверяют тесты (layout, `getBoundingClientRect`, edge-кейсы `classList`) — тесты проверяли бы jsdom, а не Bricks.
- **Матрица реальных браузеров** в CI — **отклонено**: инфраструктурная стоимость несоразмерна библиотеке ~2,2k строк; к тому же актуальные браузеры дают только *одну* ветку каждой feature-проверки.
- **Один набор тестов × сконструированные браузерные профили** — **принято**.

## Consequences

Load-bearing граница, разделяющая mock-абельное и browser-only: **mock допустим, когда host-объект — *вход* нормализации** (событие, style, document, window, XHR — объект, чей интерфейс нормализатор проверяет); **mock недопустим, когда host-API — *механизм***, на который опирается тестируемая логика (`document.cookie`-хранилище, `innerHTML`-парсер, layout-замеры типа `offsetHeight`) — тогда тест проверяет реализацию mock-а, а не Bricks. Механизм-часть модуля остаётся в реальном браузере.

Профиль — *задокументированный интерфейс* браузера, а не его реплика: тест утверждает «при каждой известной интерфейсной форме нормализатор возвращает единое поведение», а не «IE6 вёл себя именно так».

Явный seam-рефакторинг (todo 20260921-7) для тестируемости не требуется: у нормализаторов нормулируемый объект уже параметр, а в Node-харнессе глобалы (`window`, `document`) контролируются.

Механика Node-адаптера: dresscodejs не имеет CJS-таргета (вывод всегда plain-script), поэтому harness сам оборачивает скомпилированный бандл (IIFE с развёрнутыми `//#imports`) фабрикой с фиксированным списком инъекций: `BricksTest` (профили), `window`, `document`, `location`, `ActiveXObject`, `setTimeout`, `clearTimeout` (fake-часы, deterministic), `describe`, `it`, `assert`. Free-переменные бандла резолвятся в параметры; параметр `window` изолирует тест-файлы друг от друга.

Профили — plain-JS файлы `test/profile/*` (не dresscode): в Node — `require()` → параметр `BricksTest`, в браузере — один `<script>` в `test/index.html` (временная конвенция, проверяется в ходе батчей). Тестовые *среды* = профили × стрик-контекст (harness добавляет `'use strict'` в тело фабрики, отдельный помеченный проход всего сьюита) × build-флаги dresscodejs (`--set lang_ru`/`lang_en`).

Итоговый browser-минимум (батч 3, 2026-09) — механизм-часть, остающаяся в реальном браузере: `Bricks.Cookie` (document.cookie-хранилище), DOM-дерево `Bricks.DOM` (getEl/getEls/createSelectorFilter/remove/createFragment/setStyle/on/un/unAll/initDrag — реальное дерево, диспетчеризация событий, innerHTML-фрагменты), `Bricks.DOM.setStyleProperty` (layout-замеры), `Bricks.Sound._createAudioEl` (innerHTML-парсер). Всё остальное — Node-харнесс против профилей.
